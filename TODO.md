## 1. clean_stems глушит смех владельца дорожки (из код-ревью 10-09, №1)

- **Проблема**: правило «глушить всё, что недостаточно похоже на голос
  владельца» (clean_stems.py:141) убивает смех/кашель/хмыканье самого
  владельца — они не похожи на его РЕЧЕВОЙ слепок.
- **Доказательство**: work/exp_traps, смех Миши на 11.9 с: RMS 0.054 на
  сырой дорожке → 0.0002 после чистки. Каскад: Whisper не видит «ха-ха»,
  PANNs сканирует тишину — смех теряется всеми путями.
- **Фикс**: глушить только при ПОЗИТИВНОМ совпадении с профилем другого
  спикера (это голос Дэна на дорожке Миши → глушим); «ни на кого не
  похоже» — оставлять.
- **Важно (из ревью 10-09)**: править ВМЕСТЕ с шагом GROW — сейчас
  замьюченный кусок дорастает в соседние кадры «ни на кого не похоже»
  (score < OWNER_SURE), т.е. смех рядом с пролазом будет съеден ростом
  даже после смены основного правила. Новое правило роста: расти только
  в кадры, позитивно похожие на ТОГО ЖЕ чужого спикера, что и ядро.
- **Проверка**: после фикса смех Миши на 11.9 с переживает чистку
  (RMS ≈ 0.05), а известный пролаз по-прежнему глушится (контрольные
  точки в work/exp_traps и bleed_report e1v5); отдельный кейс — смех
  вплотную к замьюченному пролазу.

## 2. ✅ Мост для до-манифестных папок — v2, через accents.prev.json (10-09)

- **История**: v1 (redub сам передавал --adopt-existing) отклонён по
  возражению второго ревью: adopt штампует ТЕКУЩИЙ текст на старые
  клипы — правка «до redub» тихо исчезает (класс e1v5). Возражение
  принято, v1 откачен.
- **Фикс v2** (scripts/manifest_bridge.py): accent_texts.py сохраняет
  прежний файл как accents.prev.json (запись «из какого текста клипы
  реально пелись», mtime сохраняется); synthesize_f5.py при
  отсутствующем или старосхемном манифесте строит его из prev —
  обычное сравнение дальше пересинтезирует ровно правленые строки.
  Гард: prev новее самого свежего клипа → мосту веры нет, осторожный
  дефолт. --adopt-existing остался только для клипов без записи.
- **Проверка**: tests/test_manifest_bridge.py (6 кейсов, в т.ч. «правка
  до redub ловится»); вживую на e1v3 (1048 клипов, без манифеста):
  усыновлено 1048, к перегону 3 — два «Гельберта» (словарь улучшился)
  и один регистровый джиттер RUAccent. Весь набор 43/43.
- **Бонусы**: --dry-run у synthesize_f5 (план без загрузки модели);
  нормализация свежести не спотыкается об «R&D»→«RD».

### Раунд 3 моста (по второму пакету ревью, 10-09; СДЕЛАНО)

1. Доктор не знал о мосте → старосхемные папки (e2e2min, sent20) падали
   «все клипы STALE» до того, как synthesize успевал мигрировать.
   Теперь check_pipeline берёт ЭФФЕКТИВНЫЙ манифест через тот же
   load_or_bridge (тихо, read-only); «нет записи вовсе» — предупреждение,
   не провал (лечение — сам пересинтез).
2. Непра́вленая до-манифестная папка (accents свежи → accent_texts
   пропущен → prev нет) уходила в полный пересинтез. Теперь записью
   служит сам accents.json под тем же mtime-гардом. Проверено вживую:
   e1v2 — 941/941 усыновлены, к перегону 0.
3. Ротация prev только при реальном изменении вывода (no-op прогон
   ударений больше не хоронит запись под свежим mtime) —
   manifest_bridge.rotate_accents().
4. norm_text() — единый дом нормализации свежести (3 копии → 1),
   сравнение только по буквам/цифрам: «R&D»→«RD» и «слово,слово» ↔
   «слово, слово» не считаются правкой.
5. Мост строится по НЕфильтрованному списку (--limit-secs не сужает
   манифест); референс, перерезанный после клипов, оставляет клипы
   спикера непроверенными (3-строчный гард); O(n²)-поиск убран.
6. Тесты: +6 кейсов (всего 49/49), включая «старые accents как запись»,
   «accents новее клипов — не верить», «перерезанный референс»,
   ротацию и толерантность нормализации.

## 3. Предохранитель свежести ударений берёт в заложники --only (из код-ревью 10-09, №4)

- **Проблема**: synthesize_f5.py проверяет свежесть accents у ВСЕХ
  сегментов до применения --only. Правка текста сегмента 5 блокирует
  точечный перекат сегмента 42 (`--only 42 --seed 7` → exit 2, не спето
  ничего); подсказка про --allow-plain — неверное лекарство.
- **Фикс**: проверять свежесть только у todo-набора. Защита не слабеет:
  протухшие ударения меняют хэш манифеста → сегмент сам попадает в todo
  → под проверку. Сообщение об ошибке — перечислять протухшие id и
  предлагать accent_texts.py.
- **Реализация**: вынести проверку в manifest_bridge.stale_ids()
  (юнит-тестируема без F5); тест: правка id=5 не мешает --only 42,
  полный прогон по-прежнему ловит id=5.

## 4. assemble собирает «готовое видео» из нуля клипов (из код-ревью 10-09, №2)

- **Проблема**: assemble.py на каждый отсутствующий клип печатает
  WARNING и продолжает; порога нет. Если синтез упал целиком, на выходе
  всё равно video_ru.mp4 (музыка + вставки) и бодрое DONE.
- **Доказательство**: 10-09, Chatterbox упал на зависимости → tts_cbx
  пуст → assemble собрал video_ru_cbx.mp4 из 0/22 клипов и отчитался
  DONE; в ночной цепочке такое уехало бы в h264 и к зрителю.
- **Фикс**: считать долю отсутствующих/пустых клипов среди речевых
  сегментов; выше порога (например 10%) — абортить с перечнем id;
  осознанный обход — флаг --force-partial. Порог и в доктора (стадия
  tts уже предупреждает — сделать провалом при массовой нехватке).
- **Проверка**: пустой tts-каталог → ненулевой exit и никакого mp4;
  1 пропавший клип из 900 — предупреждение, сборка идёт.

## 5. Клипы из carry_over не попадают в манифест (из код-ревью 10-09, №5)

- **Проблема**: carry_over.py копирует подходящие wav из старого прогона
  (carry_over.py:54), но записей в tts_f5/manifest.json не делает.
  Для манифестного синтезатора эти клипы «без происхождения».
- **Последствие**: мост может их спасти только если у НОВОЙ папки уже
  есть запись-источник (prev/старые accents) — а сразу после carry_over
  её обычно нет: перевод только что применён, ударения ещё не считались.
  Итог: сотни скопированных клипов пересинтезируются — копирование
  вхолостую, часы впустую.
- **Фикс**: carry_over знает точный текст каждого перенесённого клипа
  (text_ru старого сегмента, который он и кладёт в carry.json) — пусть
  пишет манифест-записи сам: hash(спикер|старый accents-текст старого
  прогона|реф нового прогона)… аккуратно: референсы нового прогона могут
  отличаться → тогда честно НЕ записывать (клип и должен перепеться
  новым голосом). Условие: копировать клип И запись только при
  совпадении референса (hash wav старого и нового refs_f5 спикера).
- **Проверка**: тест — перенос при одинаковых refs даёт 0 к пересинтезу;
  при отличающемся ref спикера X его клипы переносятся без записи и
  честно перепеваются.

## 6. QC сверяет не с тем текстом: респеллинги вечно «MISMATCH» (из код-ревью 10-09, №6)

- **Проблема**: qc_tts.py:43 сравнивает услышанное Whisper'ом с text_ru,
  а поём мы accents-текст, где словарь намеренно респеллит
  («Гельбарта»→«Гельберта»). Такой клип — правильный — флагуется
  MISMATCH в каждом прогоне.
- **Доказательство**: e1v5 seg 12 (sim 0.33), exp_traps seg 5 — оба
  «брак» из-за задуманного «Гельберт».
- **Опасность**: любая автоматика «перепой флагнутое» (как в
  orchestrate.sh) будет вечно перекатывать ПРАВИЛЬНЫЕ клипы.
- **Фикс**: сверять с accents.json без «+» (manifest_bridge.norm_text
  уже умеет и респеллинг, и ё, и цифры-пунктуацию); script в отчёте
  показывать обоими вариантами. Заодно нормализовать числительные
  («двадцать» ↔ «20» — сегодняшние ложные флаги на числах).
- **Проверка**: клип с «Гельберт» по словарю — 0 флагов; реальный брак
  («Гилбард», лишние слова) — флагуется как раньше.

## 10. Пересохранение словарей хоронит правки в тотальном переформате (из код-ревью 10-09, №10)

- **Проблема**: правка словаря скриптом (json.dump с другим отступом)
  переписала каждую строку: homographs.json — дифф 842 строки при

  ослепло.
- **Фикс**: один раз зафиксировать канонический формат (отступ 1,
  ensure_ascii=False, ключи в исходном порядке) и правило: словари
  правятся руками или скриптом, воспроизводящим ровно этот формат;
  можно утилитой data/format_dicts.py + проверка в тестах, что
  json.dump(json.load(f)) == f.
- **Проверка**: следующая словарная правка даёт дифф в N строк, где N —
  число реально изменённых записей.
